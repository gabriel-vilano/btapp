## Visão geral

`OtpInput` é um input dedicado pra códigos one-time-password (OTP) de N dígitos. Filtra não-dígitos durante typing, foca automaticamente no mount, e usa `autocomplete="one-time-code"` pra integração com SMS auto-fill no iOS/Android. Default de 8 dígitos via constante `OTP_LENGTH`.

## Quando usar

- Verificação de email após signup
- Recuperação de senha (código enviado por email)
- 2FA / SMS / autenticação em duas etapas

## Acessibilidade

- `inputMode="numeric"` — mobile mostra teclado numérico em vez do alfabético
- `autoComplete="one-time-code"` — iOS/Android sugerem auto-fill quando detectam código no SMS
- `pattern="[0-9]*"` — backup de validação no submit
- `maxLength` aplica `length` (default 8) — impede typing além
- Foco automático ao montar — usuário não precisa clicar
- Foco indicado pela borda `border-strong` e pelo ring de `:focus-visible`; o outline nunca é removido
- Placeholder em `foreground-secondary` (4,95:1). Placeholder não é isento da [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- Mensagem de erro renderizada como `<span>` (sem `role="alert"` ainda — pode evoluir)

## Evitar

- ❌ **Aceitar caracteres não-numéricos** — o filtro `\D` no `handleChange` é proposital; não removê-lo
- ❌ **Submeter automaticamente quando completar** sem confirmação visual — o usuário deve ver os 8 dígitos antes de algo acontecer (UX padrão do iOS/Android)
- ❌ **Usar pra senhas** — OtpInput é específico pra códigos numéricos descartáveis. Senha vai em `FormInput type="password"`

## Decisões de design

**Por que um único `<input>` em vez de N inputs separados (1 por dígito)?**
N inputs separados (estilo Apple iOS) forçam JS pra mover foco entre eles, lidam mal com paste do código completo, e quebram autoComplete. Um único input com `maxLength` + filtro tem suporte nativo a paste, autoComplete e auto-fill via SMS. Trade aceito: visual menos chamativo (sem separadores entre dígitos), compensado pela robustez funcional.

**Por que constante `OTP_LENGTH` em vez de prop default 6?**
8 dígitos é decisão deliberada do projeto (Supabase Auth usa 6, mas optamos por 8 pra maior segurança). Centralizar a constante em `validations.ts` deixa consistente entre `OtpInput`, validação backend e mensagens de erro. Mudou o tamanho? Muda em um lugar.
