## Visão geral

`Icon` encapsula as convenções do design system sobre `@phosphor-icons/react`: tamanhos semânticos via prop, cor herdada via `currentColor`, e props de acessibilidade com defaults seguros. **Nenhum componente do projeto importa o Phosphor diretamente** — todo acesso passa por este wrapper.

## Variantes

Duas dimensões de variação independentes: **tamanho** (xs/sm/md/lg/xl) e **peso** (thin/light/regular/bold/fill/duotone). Combinam livremente — qualquer tamanho com qualquer peso.

## Estados

Estados de acessibilidade controlados pelas props `aria-label` e `aria-hidden`.

### Decorativo

Sem `aria-label` explícito, o ícone é tratado como puramente decorativo — `aria-hidden` aplica automaticamente. Use quando o significado do ícone já está no texto adjacente (ex: ícone ao lado de "Email", "Senha").

<Canvas of={IconStories.Decorative} />

### Com significado semântico

Quando o ícone carrega informação que não está em texto visível ao redor, fornecer `aria-label`. Leitores de tela passam a anunciar o rótulo.

<Canvas of={IconStories.Labeled} />

## Cor

`Icon` **nunca define cor própria**. O Phosphor usa `color="currentColor"` internamente, então o ícone sempre herda a cor do elemento pai via CSS.

<Canvas of={IconStories.InheritsCurrentColor} />

```css
/* Correto — cor definida no consumidor */
.navItem {
  color: var(--color-foreground-secondary);
}
.navItem--active {
  color: var(--color-foreground-accent);
}

/* Errado — não fazer */
.icon {
  color: var(--color-foreground-accent);
}
```

## Quando usar

- Acompanhando label de input ou botão (decorativo)
- Como único conteúdo de botão pequeno (com `aria-label` no botão)
- Em listas, tab bars, navegação (com peso `fill` no estado ativo)
- Status visual em alerts, toasts, badges (semântico ou decorativo conforme contexto)

## Componentes relacionados

- Para o **logo da marca**, use [`Logo`](?path=/docs/brand-logo--docs) — não é um ícone do Phosphor
- Para **ícones customizados** (SVGs próprios da marca, fora do Phosphor), criar em `src/components/icons/` como componentes próprios — não tentar passar pro `Icon`

## Evitar

- ❌ **Importar Phosphor direto no consumidor pra renderizar** — sempre via wrapper. Mantém a abstração centralizada
- ❌ **Definir cor dentro do `Icon`** — quebra `currentColor` e força sincronização manual de cor entre ícone e label
- ❌ **Usar tamanhos não-semânticos** (px arbitrários). Se o tamanho desejado não existe, expandir o sistema, não burlar
- ❌ **`aria-label` em ícone decorativo** — leitor de tela passa a anunciar redundantemente o que já está no texto

## Decisões de design

**Por que Phosphor em vez de Lucide?**
Phosphor tem suporte nativo a `fill` como variante separada (`weight="fill"`), desenhada especificamente pra funcionar preenchida — não apenas o mesmo path com `fill` aplicado via CSS. Necessário pro padrão de tab bar ativo/inativo.

**Por que wrapper em vez de importar Phosphor direto?**
Centraliza tamanhos semânticos, peso padrão e props de acessibilidade. Se amanhã o tamanho `md` mudar de 24px pra 20px, muda em um lugar só. Também impede que cor e tamanho sejam definidos ad-hoc no consumidor.

**Por que `currentColor` em vez de prop `color`?**
Composabilidade. O ícone se comporta como texto — herda a cor do contexto onde está inserido. Elimina sincronização manual de cor entre ícone e label.

**Por que ícones customizados de marca ficam fora do `Icon`?**
Logos e SVGs próprios não compartilham a API do Phosphor (peso, conjunto de tamanhos). Misturar quebra a abstração — cada caso tem seu próprio componente em `src/components/icons/`.
