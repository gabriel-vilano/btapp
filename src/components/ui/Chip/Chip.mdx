## Visão geral

O chip é uma pílula de 40px com uma opção curta, um número ou uma ou duas palavras. Ele aparece em fileira, nunca sozinho, e mostra de uma vez todas as opções que o jogador pode tocar.

<Canvas of={ChipStories.AllVariants} />

## Variantes

As duas variantes têm o mesmo visual e semânticas diferentes. A escolha depende do que o toque faz: aplica um filtro na tela ou marca a resposta de um formulário.

### Chip de filtro

`FilterChip` é um botão de alternância (`aria-pressed`). Liga e desliga um filtro, e a tela reage na hora. Selecionado, ganha um check à esquerda. É o filtro de categoria do ranking e, no futuro, o da descoberta.

<Canvas of={ChipStories.Filter} />

O estado de cada chip é do consumidor. Para uma categoria por vez, o consumidor desliga os outros; para vários filtros ao mesmo tempo, cada chip guarda o próprio estado. Uma fileira de filtros vai dentro de um `role="group"` com `aria-label`.

<Canvas of={ChipStories.FilterGroup} />

### Chip de escolha em grupo de rádio

`ChoiceChipGroup` é um grupo de rádios nativos com cara de chip, para escolher uma opção entre poucas. É a entrada dos games de quem perdeu o set, no registro de partidas: o jogador escolhe quem venceu e toca nos games de quem perdeu, e o app monta o placar. Só existem placares válidos.

<Canvas of={ChipStories.ChoiceGames} />

No set de 8 são nove chips, que quebram em duas linhas em 393px. Quem monta a tela decide se isso basta ou se a entrada precisa de outro arranjo.

<Canvas of={ChipStories.ChoiceGamesSetOf8} />

As opções também podem ser texto, como no motivo da contestação.

<Canvas of={ChipStories.ChoiceText} />

## Estados

Os estados valem para as duas variantes.

### Selecionado

A seleção é um state layer (`--color-state-layer-selected`) sobre o fundo, com a borda em `--color-border-strong` e 2px de espessura. Hover e press empilham por cima, então o chip selecionado também reage ao toque. No filtro, o check reforça a seleção sem depender de cor.

<Canvas of={ChipStories.FilterSelected} />

### Rótulo do grupo escondido

`hideLabel` tira o rótulo da tela e o mantém para o leitor de tela. Use quando a tela já diz o que o grupo pergunta, como um título de set logo acima.

<Canvas of={ChipStories.ChoiceHiddenLabel} />

### Desabilitado

O grupo inteiro (`disabled`) ou uma opção (`options[].disabled`). O chip desabilitado não reage a hover nem a toque.

<Canvas of={ChipStories.ChoiceDisabled} />

<Canvas of={ChipStories.FilterDisabled} />

## Quando usar

- Filtrar uma lista por um atributo curto, como a categoria do ranking
- Escolher um valor entre poucos, curtos e visíveis de uma vez, como os games de um set
- Responder uma pergunta de lista curta num formulário, como o motivo da contestação

## Componentes relacionados

- Para **escolher entre 2 ou 3 modos que mudam a tela inteira** ("como terminou a partida"), use o SegmentedControl, quando existir
- Para **um número numa faixa longa** ou sem valores fixos (o set interrompido), use o Stepper, quando existir
- Para **uma ação**, use [`Button`](?path=/docs/ui-button--docs). O chip marca uma escolha, não dispara uma ação
- Para **mostrar um status** sem interação, use o Badge

## Acessibilidade

- **Filtro:** `<button type="button" aria-pressed>`. O leitor de tela anuncia "botão de alternância, pressionado" ([APG Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/))
- **Escolha:** `<fieldset>` com `<legend>` e `<input type="radio">` nativos. O leitor anuncia o grupo pelo nome e "botão de opção, 4 de 7". Tab entra no grupo; as setas trocam a opção ([APG Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/))
- O `label` do grupo é obrigatório, mesmo com `hideLabel`: sem ele, "4" não diz de quem são os games
- **Área tocável de 48px** num chip de 40px, via `::before`. Com o gap de 8px do grupo, as áreas de chips vizinhos se encostam sem se sobrepor
- **Foco:** o ring do DS em `:focus-visible` (no rádio, o ring aparece no chip)
- **Seleção sem depender de cor** (WCAG 1.4.1): borda de 2px em `--color-border-strong`, fundo e, no filtro, o check

## Evitar

- ❌ **Chip de filtro para responder um formulário.** A resposta é escolha única com semântica de rádio: use `ChoiceChipGroup`
- ❌ **Chip sozinho.** Um só filtro liga/desliga é um switch ou checkbox
- ❌ **Texto longo.** Uma ou duas palavras. Opção que precisa de frase vai num rádio com label comum
- ❌ **Muitas opções.** Acima de umas 10, o jogador não vê tudo de uma vez: use lista ou Stepper
- ❌ **Gap menor que 8px entre chips.** As áreas tocáveis de 48px passam a se sobrepor

## Decisões de design

**Por que dois componentes e não um `Chip` com prop `variant`?** Porque a diferença é de semântica, não de visual. O filtro é um botão com estado próprio; a escolha é um rádio que só faz sentido dentro de um grupo com nome. Uma prop `variant` deixaria montar um rádio solto, sem grupo, que o leitor de tela anuncia sem contexto.

**Por que rádio nativo em vez de `role="radio"` num botão?** O rádio nativo já traz as setas do teclado, o foco num item só do grupo (roving tabindex) e o envio em formulário. Com ARIA, o componente teria que reimplementar tudo isso.

**Por que a seleção é um state layer e não coral?** O coral é a cor de ação do app. Um grupo de chips selecionados em coral competiria com o botão primário da tela, e o placar tem vários grupos na mesma tela. O state layer segue o padrão de camadas do DS (`docs/TOKENS.md` > "State layers").
